# وسيط حصص الأوقاف لوِرد — نموذج أولي للمراجعة

هذا مصدر وسيط جلب مستقل. الربط بتطبيق Android لا يعتمد قبل نجاح الجلب الحي. لا توجد جداول رسمية مضمّنة في المصدر. حالة كل تشغيل موجودة في api/v1/sync-status.json على فرع prayer-data.

## ماذا تفعل؟
- تجلب صفحة الحصة الشهرية عبر HTTPS من نطاقي الأوقاف فقط.
- تستخدم شهادات النظام مع Sectigo R46 وDV R36 بعد فحص بصمتيهما؛ يبقى التحقق من الشهادة واسم الخادم مفعلاً.
- تتحقق من هوية المدينة والتواريخ الميلادية والسنة وأيام الأسبوع وتسلسل الأيام والصلوات الست.
- تستبعد اليوم 30 المشروط بعبارة «حسب رؤية الهلال» عند وجود 29 يوماً مؤكداً.
- تنتج JSON مستقلاً لكل معرّف مدينة. الاسم المكرر لا يخلط الحصص لأن المفتاح هو المعرّف.
- تكتب الملف الجديد بشكل ذري بعد نجاح التحليل. فشل الجلب لا يستبدل آخر ملف محفوظ ولا يضيف حساباً فلكياً تحت اسم الوزارة.
- تتوقف مبكراً بعد فشلين متتاليين لتجنب تكرار الطلبات أثناء انقطاع عام.

## التشغيل
يلزم Python 3.10 أو أحدث، بدون مكتبات إضافية:

```bash
python3 -m unittest discover -s tests -v
python3 sync.py --city 158
python3 sync.py
```

الأمر الأول اختبارات ببيانات اصطناعية. الثاني يجلب بوجدور. الثالث يحاول جميع المعرفات الـ191 في الفهرس الحالي، ولا يثبت أن الفهرس مطابق لآخر تغييرات الوزارة.

النتائج تحت public/api/v1:
- 158.json: حصة بوجدور عند نجاح جلبها فقط.
- catalog.json: المعرفات والأسماء.
- sync-status.json: حالة آخر محاولة لكل مدينة جرت محاولتها. لا يعني اكتمال المدن التي لم تجر محاولتها.

أكواد الخروج: 0 عند نجاح كل المدن المطلوبة، و1 عند أي فشل أو عدم اكتمال الدفعة. راجع ملف الحالة للتفصيل.

## النشر المقصود
1. شغّل sync.py في خادم يدعم Python أو مهمة GitHub Actions مجدولة.
2. احتفظ بمجلد public بين التشغيلات لاستبقاء آخر حصص صالحة. بيئة CI مؤقتة تحتاج استرجاع الملفات المنشورة أولاً.
3. بعد نجاح جلب حصص حقيقية، انشر محتويات public على Cloudflare Pages أو استضافة HTTPS ثابتة موثوقة.
4. يصبح المسار المتوقع https://YOUR_HOST/api/v1/158.json؛ هذا مثال وليس رابط خدمة موجودة.
5. بعدها فقط يضاف الرابط المعتمد إلى عميل Java، مع فحص المدينة والتاريخ والمصدر والتغطية قبل الحفظ المحلي.

Cloudflare Pages تخدم ملفات JSON الناتجة؛ رفع سكربت Python إليها وحده لا يشغله كمهمة مجدولة. هذه الحزمة لا تتضمن بيانات دخول أو نشراً تلقائياً.

مقترح التجديد: مرتان يومياً مع معالجة نهاية الشهر. لا نفترض ثبات السنة أو توفر جداولها مسبقاً. لا تعاد تسمية حصة سنة قديمة للسنة الحالية.

## عقد البيانات والتوقيت
schema=1، source=habous.gov.ma، cityId، timezone=UTC، fetchedAt بالميلي ثانية، firstDate، lastDate، days. كل يوم يحمل dateKey بصيغة YYYY-MM-DD وtimes بساعة 24 ساعة.
يعكس UTC عقد وِرد الحالي للمقارنة مع الحصة. قبل أي اعتماد عام، تحقق من أساس توقيت الحصة المنشورة ومن التحويل إلى توقيت الجهاز مرة واحدة. لا يضيف الوسيط ساعة أو دقيقتين ولا يصحح الأرقام الفلكية.
يجب على التطبيق رفض يوم غير مغطى أو مدينة مختلفة، وعدم إعادة استعمال يوم قديم. حساب Adhan الاحتياطي يبقى مميزاً عن الوزارة.

## ما تحقق فعلاً في 16 أكتوبر 2026
نجحت 7 اختبارات تشمل جميع معرفات الفهرس، وفصل التخزين، ورفض الصفوف المعطوبة، وترحيل السنة، والصف المشروط، وبقاء الملف السابق عند فشل الشبكة، ورفض تحويل إلى HTTP أو موقع آخر.
محاولة الجلب الحي لبوجدور من بيئة العمل أعادت HTTP 502 على المسارات الأربعة. لم ينتج عنها ملف حصة رسمي، ولا نستنتج أن خادم الوزارة نفسه هو مصدر 502. لم يختبر النشر أو الاتصال من Android عبر وسيط.

الحدود: HTML الفعلي الحي ما زال غير متاح للاختبار هنا. استرجعت صفحات فعلية لبوجدور والرباط عبر GitHub Actions وأضيفت اختبارات عليها. لا تكفي اختبارات البيانات الاصطناعية لإعلان دقة جميع المدن.
